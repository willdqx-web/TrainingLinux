## 1. 標準入出力の概念

### コマンドの「入口」と「出口」

Linuxのすべてのコマンドは「3本のチャンネル」を持っている。

```
              ┌──────────────────┐
stdin(0)  ───▶│   コマンド        │──▶ stdout(1)  通常の出力
              │   (例：ls, grep)  │──▶ stderr(2)  エラー出力
              └──────────────────┘
```

| チャンネル | 番号 | デフォルトの行き先 |
|-----------|------|----------------|
| stdin（標準入力） | 0 | キーボード |
| stdout（標準出力） | 1 | ターミナル画面 |
| stderr（標準エラー出力） | 2 | ターミナル画面（エラーのみ） |

Windowsにも同じ概念があるが（コマンドプロンプトのリダイレクト `>` など）、Linuxではより柔軟に扱える。

## 2. リダイレクト

### 出力をファイルに保存する（`>`）

```bash
ls -l > filelist.txt        # ls の出力をファイルに保存（上書き）
ls -l >> filelist.txt       # 追記（上書きではなく末尾に追加）
```

> **注意**：`>` は既存ファイルを上書きする。誤って重要なファイルを上書きしないよう注意。

### エラー出力をファイルに保存する（`2>`）

```bash
gcc main.c 2> errors.txt        # コンパイルエラーをファイルに保存
gcc main.c 2>> errors.txt       # 追記
```

**なぜ `2>` が必要か**：コンパイルエラーはstderrに出力される。`>` だけではstderrは画面に残る。

```bash
# stdout と stderr の両方をファイルに保存する
gcc main.c > build.log 2>&1
#               stdout→ファイル  stderr→stdout（= 結局ファイル）

# stdout と stderr を別ファイルに保存する
gcc main.c > output.txt 2> errors.txt
```

### 出力を捨てる（`/dev/null`）

`/dev/null` はLinux特有の「ゴミ箱デバイス」。書き込んだデータはすべて捨てられる。

```bash
find / -name "*.c" 2>/dev/null      # エラーメッセージを捨てる（権限エラーを非表示）
```

## 3. パイプ（`|`）

### パイプとは

あるコマンドの**stdout（出力）**を、次のコマンドの**stdin（入力）**に直接つなぐ仕組み。

```
コマンドA の出力  ────────▶  コマンドB の入力  ────────▶  画面
                  パイプ（|）
```

ファイルを介さずにコマンドをつないで、複雑な処理を1行で書ける。

```bash
# ファイルなしで組み合わせる例：
ls -l | grep ".c"       # ls の出力から .c を含む行だけ表示
ps aux | grep vim       # 実行中のプロセスから vim を探す
cat errors.txt | sort   # ファイルをソートして表示
```

### テキスト処理コマンドとの組み合わせ

| コマンド | 役割 | 使用例 |
|---------|------|-------|
| `sort` | 行をソート | `cat list.txt \| sort` |
| `uniq` | 連続する重複行を削除 | `sort list.txt \| uniq` |
| `wc` | 行数・単語数・バイト数を数える | `ls \| wc -l`（ファイル数を数える） |
| `head` | 先頭N行を表示 | `cat log.txt \| head -20` |
| `tail` | 末尾N行を表示 | `cat log.txt \| tail -20` |
| `cut` | フィールドを切り出す | `cat data.csv \| cut -d',' -f1` |
| `tr` | 文字を置換・削除 | `cat file.txt \| tr 'a-z' 'A-Z'`（小文字→大文字） |

### ビルドログの解析に使う実践例

組み込み開発でよく使うパターン：

```bash
# コンパイルエラーだけを抽出する
make 2>&1 | grep "error:"

# 警告の数を数える
make 2>&1 | grep "warning:" | wc -l

# ファイルごとのエラーを確認する
make 2>&1 | grep "error:" | cut -d':' -f1 | sort | uniq
```

## 4. シェルの便利な機能

### コマンド履歴

```bash
history                 # 過去に実行したコマンド一覧
history | grep gcc      # gccを含むコマンドを検索
!500                    # 履歴の500番目のコマンドを実行
!!                      # 直前のコマンドを再実行
Ctrl + r                # 履歴を逆方向にインクリメンタル検索
```

### Tab補完

コマンド名やファイル名の途中でTabを押すと補完される。

```bash
ls ~/train  [Tab]   # ~/training/ に補完される
gcc ma      [Tab]   # main.c など候補を表示
```

## 5. プロセス管理

### プロセスとは

実行中のプログラムの単位。コマンドを実行するたびにプロセスが生成される。Windowsのタスクマネージャーで見えるものに相当する。

```
プロセス = 実行中のプログラム + そのリソース（メモリ、CPU使用など）
```

### `ps`：プロセスを表示する

```bash
ps              # 現在のターミナルに関連するプロセスを表示
ps aux          # すべてのプロセスを詳細表示
ps aux | grep vim   # vim プロセスを探す
```

`ps aux` の出力の読み方：

```
USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root         1  0.0  0.5  21892  5120 ?        Ss   10:00   0:01 /sbin/init
user      1234  0.1  0.3  12345  3456 pts/0    S    10:05   0:00 vim main.c
```

| 列 | 意味 |
|----|------|
| `USER` | プロセスの所有者 |
| `PID` | プロセスID（プロセスを識別する番号） |
| `%CPU` | CPU使用率 |
| `%MEM` | メモリ使用率 |
| `STAT` | プロセスの状態（S=スリープ、R=実行中、Z=ゾンビ） |
| `COMMAND` | 実行しているコマンド |

### `top`：リアルタイムでプロセスを監視する

```bash
top
```

Windowsのタスクマネージャーに相当。CPU使用率の高い順にプロセスが並ぶ。

操作方法：
- `q`：終了
- `k`：プロセスを kill する（PIDを入力）
- `1`：CPUコアごとの使用率を表示

### `kill`：プロセスを終了させる

```bash
kill 1234           # PID 1234 のプロセスに SIGTERM を送る（丁寧に終了要求）
kill -9 1234        # SIGKILL を送る（強制終了。データが失われる可能性あり）
killall vim         # vim という名前のすべてのプロセスを終了
```

**シグナルの使い分け**

| シグナル | 番号 | 動作 |
|---------|------|------|
| SIGTERM | 15 | 終了要求（プログラムがクリーンアップできる） |
| SIGKILL | 9 | 強制終了（即座に終了。クリーンアップなし） |
| SIGHUP | 1 | 再起動シグナル（設定ファイルの再読み込みなど） |

組み込み開発での用途：プロセスが応答しなくなった場合や、ビルドスクリプトが暴走した場合に使う。

### バックグラウンド実行（`&`）

コマンドの末尾に `&` をつけると、バックグラウンドで実行される（ターミナルに制御が戻る）。

```bash
./long_build.sh &       # バックグラウンドでビルドを実行
# [1] 5678              # ジョブ番号とPIDが表示される
# ターミナルが戻ってくる → 他のコマンドを実行できる
```

`jobs`、`fg` でバックグラウンドジョブを管理する：

```bash
jobs                    # バックグラウンドジョブの一覧
fg %1                   # ジョブ1番をフォアグラウンドに戻す
Ctrl + Z                # 実行中のプロセスを一時停止（サスペンド）
bg %1                   # 一時停止中のジョブをバックグラウンドで再開
```

## よくあるエラーと対処法

| エラー | 原因 | 対処 |
|--------|------|------|
| `bash: command not found: gcc` | パスが通っていない or インストール未完了 | `which gcc` で確認。なければ `sudo apt install build-essential` |
| `kill: (1234): Operation not permitted` | 他ユーザーのプロセスを kill しようとした | `sudo kill 1234` で root 権限が必要 |
| `kill -9` を使っても終了しない | カーネルが処理中（I/O待ちなど）でシグナルを受け付けない | 状態が変わるのを待つ（強制は無理なことがある） |
| パイプが止まる | 前のコマンドが終了せず出力を送り続けている | `Ctrl + C` でパイプ全体を中断する |
| `>` でファイルが空になった | コマンドの前に `>` を書いてしまった | `>` はコマンドの**後**に書く。`> file cmd` は誤り |
